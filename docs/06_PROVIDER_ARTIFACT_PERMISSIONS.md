# Provider Artifact Permission Plan

This document tracks what we need before importing post-meeting artifacts from
Zoom, Google Meet, and Microsoft Teams. Calendar OAuth is already useful for
meeting discovery, but it does not automatically grant access to recordings,
transcripts, chats, notes, or files.

Use this checklist before implementing any provider-specific artifact importer.
Provider permission names change over time, so verify the official docs again
before adding scopes to production OAuth consent screens.

## Product Rule

Do not request artifact scopes until the user is enabling artifact import for a
specific provider. The default calendar connection should stay low-friction and
limited to calendar event sync.

When artifact import is enabled, the UI should clearly say:

- which provider is being connected
- which artifact types the app will try to read
- whether admin consent is required
- whether the provider only exposes artifacts created by the signed-in user,
  meeting organizer, tenant, or installed meeting/chat app
- that recordings/transcripts must already exist in the provider before import

## Current App Scopes

These are discovery-only scopes, not artifact-import scopes.

| Provider | Current purpose | Current scopes |
| --- | --- | --- |
| Google | Calendar event discovery | `openid`, `email`, `profile`, `https://www.googleapis.com/auth/calendar.events.readonly` |
| Microsoft | Outlook calendar event discovery | `openid`, `email`, `profile`, `offline_access`, `User.Read`, `Calendars.Read` |
| Zoom | Not connected yet | None |

## Google Meet

Google Meet artifacts are accessed through the Meet REST API and sometimes
through Drive/Docs because Meet stores recordings and transcripts there.

What can be imported:

- recordings metadata from Meet conference records
- transcript metadata from Meet conference records
- transcript entries from the Meet API while retained
- recording/transcript files from Drive when the user has access
- smart notes where the API exposes them and the user's account supports them

Likely requirements:

- Enable Google Meet REST API in the Google Cloud project.
- Keep Google Calendar event sync for event discovery and Meet links.
- Add Meet scopes only when enabling Google Meet artifact import:
  - `https://www.googleapis.com/auth/meetings.space.readonly`
- Add Drive read scope only when downloading files:
  - Prefer `https://www.googleapis.com/auth/drive.meet.readonly` when it covers
    the artifact path.
  - Use `https://www.googleapis.com/auth/drive.readonly` only if required,
    because it is a broad restricted scope.
- If reading transcript file content through Google Docs instead of Meet
  transcript entries, verify whether a Docs read scope is required for the chosen
  implementation path.
- Restricted Google scopes can require OAuth app verification and, when data is
  stored or transmitted server-side, a security assessment.

Important constraints:

- Meet REST API access uses user authentication. A service account requires
  domain-wide delegation and still impersonates a user.
- Artifacts must be generated by Meet before import.
- Meet artifacts can be deleted or retained under Drive/Vault rules.
- Transcript entries from the Meet REST API have limited retention, so we should
  import soon after the meeting ends when this path is used.
- The signed-in user must have access to the meeting/conference artifacts.

Recommended first implementation:

1. Use calendar events to identify likely Google Meet meetings.
2. Add a Google artifact capability/status endpoint that reports missing Meet or
   Drive scopes.
3. Probe the Meet REST API for conference records and transcript/recording
   metadata.
4. Import transcript entries first, because they are smaller and cheaper than
   video files.
5. Download recording files only after the user explicitly requests it.

## Microsoft Teams

Microsoft Teams transcripts and recordings are exposed through Microsoft Graph.
This is more permission-heavy than simple Outlook calendar sync.

What can be imported:

- Teams meeting transcripts
- Teams meeting recordings
- transcript/recording availability notifications
- user-scoped, meeting-scoped, or tenant-scoped artifacts depending on the
  permission model

Likely requirements:

- Microsoft Entra app registration.
- Current calendar scopes for event discovery:
  - `Calendars.Read`
  - `offline_access`
- Additional Graph permissions for online meeting artifact import, chosen by
  scope model:
  - `OnlineMeetingTranscript.Read.All`
  - `OnlineMeetingRecording.Read.All`
  - resource-specific consent permissions such as
    `OnlineMeetingTranscript.Read.Chat` or `OnlineMeetingRecording.Read.Chat`
    when building a Teams app installed in the meeting/chat context
- Admin consent is usually required for broad recording/transcript permissions.
- For organization-wide application permissions, configure the required
  application access policy before expecting production access.
- Microsoft meeting APIs can be metered, so cost/usage limits need to be visible
  before enabling automatic imports.

Important constraints:

- Calendar events alone do not provide transcript/recording access.
- Some Graph transcript/recording APIs behave differently for scheduled online
  meetings, channel meetings, and ad hoc calls.
- Notifications are the preferred way to know when a transcript or recording is
  available, but the MVP can start with an explicit probe/sync action.
- Tenant policies, organizer identity, and meeting type can block access even
  when OAuth succeeds.

Recommended first implementation:

1. Extend Microsoft provider status to report whether artifact scopes are present.
2. Add a Teams artifact probe for a linked calendar event with an online meeting.
3. Import transcript `.vtt` content before downloading `.mp4` recordings.
4. Add change notifications only after the manual/probe path is reliable.

## Zoom

Zoom artifact import should be implemented as its own provider connection, not
as part of Google/Microsoft calendar OAuth. Zoom meetings found in calendar
events can be matched by join URL, meeting ID, topic, and start time.

What can be imported:

- cloud recording metadata
- recording files
- audio transcript files when Zoom generated them
- chat files, timeline, summaries, or other cloud recording artifacts where the
  account plan and API scopes expose them
- recording availability events through webhooks

Likely requirements:

- Zoom OAuth app or Server-to-Server OAuth app, depending on whether imports are
  user-scoped or account-scoped.
- Zoom cloud recording enabled for the account/user.
- Audio transcription enabled if we expect Zoom-generated transcript files.
- Recording read scopes. Verify the current Zoom Marketplace scope names for the
  chosen app type before implementation. Common current scope families include:
  - `cloud_recording:read:recording`
  - `cloud_recording:read:recording:admin`
  - `cloud_recording:read:list_recording_files`
  - `cloud_recording:read:list_recording_files:admin`
- Webhook scope for `recording.completed` if we add event-driven import.

Important constraints:

- Local Zoom recordings are not generally available through Zoom cloud recording
  APIs.
- The original host/account often owns the cloud recording, even if another
  participant joined or was promoted during the meeting.
- Some Zoom scopes are only available for certain app types or account levels.
- Webhooks are useful for production but should come after a manual import/probe
  flow.

Recommended first implementation:

1. Add a Zoom provider status endpoint with configuration and scope guidance.
2. Parse Zoom meeting IDs from imported calendar event links.
3. Add a manual "Find Zoom artifacts" probe for a linked event.
4. Import Zoom audio transcript files first when present.
5. Fall back to downloading audio/video and using local Whisper only when the user
   requests it.

## Cross-Provider Implementation Checklist

- [ ] Keep provider connections separate from calendar accounts where the
      permission model is different.
- [ ] Store artifact provider, provider artifact ID, artifact type, source URL,
      import status, imported time, and source metadata.
- [ ] Never persist raw OAuth tokens outside encrypted token storage.
- [x] Add provider capability/status endpoints before adding import buttons.
- [ ] Add a manual probe endpoint before any automatic artifact import job.
- [ ] Import text transcripts before large recording files.
- [ ] Display clear "not available yet", "missing permission", and "admin consent
      required" states.
- [ ] Avoid broad tenant-wide permissions until there is a clear workspace admin
      flow.
- [ ] Keep local upload/transcription as the fallback for unsupported providers
      or missing permissions.
